# 一键配置文件操作日志设计

## 目标

在 Rust/Tauri 版本的一键配置流程中，记录真实发生的阶段和文件操作，并在“运行日志”页展示，方便用户判断配置失败发生在哪个客户端、哪个文件和哪个步骤。

## 范围

- 记录部署、工具索引刷新、客户端配置、备份、写入、回读、冲突、回滚和最终结果。
- 日志保存在当前 AppState 内存中，重启后不恢复；不改变现有日志文件和授权缓存格式。
- 不记录 CDK 内容、用户文件内容或私钥内容，只记录路径、操作、状态和验证摘要。
- 不修改配置事务顺序，不降低现有冲突保护和回滚保护。

## 数据流

`configure_selected` 在调用核心服务前写入开始日志；服务进度回调写入 deploy/refresh/configure 阶段日志；服务返回 `ClientResult` 后，Tauri 层从 `FileResult` 和 `restored` 生成每个规则文件/MCP 文件的备份、写入、回读和恢复日志；前端从 `BootstrapState.logs` 读取并按时间顺序展示。

## 日志字段

每条日志保留时间、级别和用户可读消息，并增加可选结构化字段：

- `phase`: `deploy`、`refresh`、`configure`、`rollback`、`complete`、`error`
- `operation`: `start`、`backup`、`write`、`readback`、`restore`、`summary`
- `clientId`: 相关客户端 ID；阶段日志为空
- `target`: 目标文件路径；非文件日志为空
- `status`: `success`、`failed`、`rolled_back` 等；阶段日志为空

前端在保持现有中文消息的同时，以 `[阶段] [操作]` 前缀和目标路径显示字段。路径和消息允许换行，避免长 Windows 路径被截断。

## 错误处理

- payload 或 tool-index 阶段失败：记录失败阶段和错误消息。
- 单个客户端回滚：记录客户端状态、失败消息和每个恢复目标。
- 成功文件：分别记录规则文件和 MCP 文件的备份/写入/回读证据。
- 日志记录失败不能影响配置事务结果。

## 验收标准

1. 一键配置开始后，日志页能看到部署和 tool-index 阶段。
2. 每个成功客户端至少出现规则文件和 MCP 文件的目标路径及回读成功日志。
3. 冲突或失败时显示失败目标和回滚目标。
4. 日志字段序列化为现有 camelCase IPC 合同。
5. Rust、UI、类型检查和构建测试全部通过。
