# Wujin 2.0.2 V45 Paid Addon Design

## Goal

Update the Windows source version to `2.0.2`, replace the pinned paid GPT-5.6
runtime with upstream v45, and add a selected instruction/Skill subset from
`lingbol088-spec/codex-gpt-5.6-5.5-instruct` to the CDK-gated Codex one-click
configuration path.

This change is source and debug-test work only. It does not build, sign, bundle,
publish, upload, or update the production manifest or website.

## Paid Asset Layout

- `assets/codex/gpt-5.6-instruct-v45/` contains only the exact v45 runtime,
  upstream MIT license, and immutable `SOURCE.json` evidence.
- `assets/codex/gpt-5.6-5.5-instruct-addon/` contains the exact upstream bridge,
  selected non-overlapping Skill files, upstream MIT license, a deterministic
  file manifest, a Wujin routing index, and immutable source evidence.
- The add-on excludes upstream deploy/remove scripts, BAT launchers, backup
  bridges, MCP servers, tool downloaders/launchers, hard-coded-path Skills,
  placeholder Skills, and the six Skill IDs already supplied by NERV.

## One-Click Behavior

The existing CDK-gated Codex adapter remains the only writer. It validates all
three paid asset roots before changing user files. The single
`model_instructions_file` continues to reference one deterministic combined
file containing v45, the existing NERV bridge, and the selected add-on bridge.
The managed Codex `AGENTS.md` block references both NERV and add-on routing
indexes. No new MCP server is registered.

Existing conflict detection, atomic writes, backup, readback validation, and
rollback behavior remain unchanged. Legacy Wujin v5 and current managed paths
remain recognized migration inputs.

## Supply Chain

Every vendored byte is pinned to an immutable repository commit and checked by
SHA-256. The paid gates enforce top-level allowlists, safe paths, manifest order,
file sizes and hashes, exact selected Skill IDs, payload presence, and free
bundle isolation. Modified or untracked upstream files are excluded.

## Version And Release Boundary

All enforced application version surfaces move from `2.0.1` to `2.0.2`.
Release approval strings move with the source contract so stale approvals fail,
but no release command is executed in this task. Existing CDK, receipt, update
signature, free/paid isolation, and website state remain unchanged.

## Acceptance

- Paid v45, NERV, and add-on supply-chain tests pass.
- Codex adapter tests prove both routing files and the v45/add-on combined prompt.
- Existing model/MCP conflict and rollback tests continue to pass.
- Version-contract tests report `2.0.2` everywhere.
- The non-packaging full gate passes with `-SkipReleaseBuild`.
