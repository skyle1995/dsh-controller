# 无限破甲 15 秒竖屏 UI 动画设计

日期：2026-07-25
状态：已由主人确认创意、分镜、视觉规范与制作方案

## 1. 目标

制作一条约 15 秒的无限破甲产品 UI 动画，用于抖音竖屏信息流。成片需要在前三秒抓住注意力、七秒内讲清“一键配置 AI 破甲环境”的核心价值，并在结尾形成“无限破甲，让 AI 真正开始工作”的品牌记忆。

成片按大师级商业产品动效标准制作：镜头、界面、排版、音效和音乐必须共享同一节奏系统。动效强度要高，但所有视觉效果都服务于产品信息，不堆叠无意义炫光或廉价转场。

## 2. 固定交付规格

- 画幅：9:16 竖屏
- 分辨率：1080×1920
- 帧率：30 FPS
- 时长：目标 15.0 秒，允许误差不超过 0.1 秒
- 视频编码：H.264，`yuv420p`
- 音频编码：AAC，48 kHz
- 主成片：`无限破甲-UI动画-15s-1080x1920.mp4`
- 封面帧：`无限破甲-UI动画-封面.png`
- 源文件：可本地重复渲染的 HTML、CSS、JavaScript、音频生成与导出脚本
- 制作目录：`运营文案和视频/无限破甲-15s-UI动画/`

## 3. 已确认的创意方向

采用“真实 UI 冲刺”方案。画面延续无限破甲当前浅色产品 UI，以真实界面结构为基础重构竖屏镜头，而不是把横屏截图整体缩小塞进手机画幅。

核心传播目标：突出“一键配置 AI 破甲环境”。
收尾主文案：**无限破甲，让 AI 真正开始工作**。
声音策略：电子节拍、原创 UI 音效、无配音。

## 4. 时间轴与分镜

### 0.0–1.3 秒：品牌启动

- 浅灰白背景从纯白中显现，加入极轻的技术网格和空间层次。
- 无限破甲六边形图标以品牌红线条快速绘制。
- 标题“让 AI 真正开始工作”按语义分组进入。
- 镜头快速建立品牌后立即推进，不停留成静态片头。

### 1.3–4.2 秒：智能识别

- 产品窗口从画面下方升入，带轻微透视并在落位时回正。
- 镜头由完整窗口推进到“选择 AI 客户端”区域。
- 扫描线经过客户端卡片，Codex 卡片出现路径追踪、高亮描边、磁吸对齐和勾选反馈。
- 辅助字幕：“自动识别本机 AI 客户端”。

### 4.2–7.0 秒：进入配置

- 虚拟光标移动到“下一步：激活产品”，按压时按钮缩放并产生克制的品牌红能量波纹。
- 点击动作直接驱动页面横向推进，光标、按钮和转场形成一个连续动作。
- 新页面聚焦“一键配置”按钮。
- 辅助字幕：“复杂配置，交给无限破甲”。

### 7.0–11.5 秒：一键完成

- 点击“一键配置”后，红色光带沿数据路径依次穿过三个状态节点：
  1. 环境检测
  2. Skill 路由注入
  3. 配置验证
- 每个节点依次出现运行态、完成态和绿色勾选，卡在音乐节拍上。
- 最后一个节点完成时，粒子向中心汇聚形成“配置成功”标记，界面产生一次轻微景深呼吸。

### 11.5–15.0 秒：品牌收尾

- UI 卡片与数据路径快速归拢，运动轨迹汇聚成无限破甲 Logo。
- 红色轨迹扫出产品名与主文案：
  - “无限破甲”
  - “让 AI 真正开始工作”
- 底部小字：“一键配置 AI 破甲环境”。
- 最终品牌画面稳定停留至少 1 秒。

## 5. 视觉系统

### 5.1 色彩

- 背景浅灰白：`#F4F7FB`
- 主背景白：`#FFFFFF`
- 品牌红：`#FF3B3F`
- 成功绿：`#28B779`
- 主文字深蓝黑：`#0F1B2D`
- 次级文字灰蓝：`#69778C`
- 描边：`#D8E0EA`

品牌红负责路径、按钮和关键节拍；成功绿只在完成反馈出现，避免与主品牌色争夺注意力。

### 5.2 字体与排版

- 中文优先使用思源黑体；系统缺失时回退到 Microsoft YaHei、sans-serif。
- 标题使用 SemiBold，正文使用 Regular。
- 字幕按语义分组出现，不做逐字弹跳。
- 核心文案保持在抖音安全区内，避开顶部信息区、底部标题区和右侧交互按钮区。

### 5.3 深度与材质

- 背景、主窗口、卡片、文字和光标至少分成四个空间层级。
- 通过阴影、缩放、位移和轻微模糊形成景深，不使用重度玻璃拟态。
- 所有卡片保持产品现有圆角、浅色描边和清晰信息层级。

## 6. 动效语言

- 总体节奏：快启、短停、爆发、收束。
- 主镜头使用缓入缓出与惯性衔接；微交互使用短促弹簧回弹。
- 按钮按下先缩放至约 96%，再快速回弹。
- 勾选通过路径绘制完成，不能只做透明度切换。
- 页面切换主要使用容器位移和遮罩，不使用模板化旋转翻页。
- 识别动作由扫描线、路径追踪、高亮描边和磁吸落位组成。
- 配置动作由同一条品牌红光带贯穿，保证过程连续可读。
- UI 收尾变形为 Logo 时，元素必须有明确来源和终点，避免凭空出现。
- 微光、粒子、运动模糊和景深只在节拍峰值使用。

## 7. 制作架构

### 7.1 模块边界

- `index.html`：固定舞台、语义化场景容器和可测试元素标识。
- `styles.css`：品牌变量、竖屏 UI、空间层级和静态视觉状态。
- `timeline.js`：唯一时间源；将 0–15 秒映射到镜头、界面和文字状态。
- `components.js`：Logo、客户端卡片、光标、步骤节点、成功状态等独立组件。
- `audio/`：原创节拍与 UI 音效。
- `scripts/render.*`：逐帧捕获、音视频合成和封面输出。

各组件只接收归一化进度或离散状态，不自行读取系统时间。这样可以逐帧确定性渲染，也方便在任意时间点生成检查帧。

### 7.2 数据流

```text
render time
  -> master timeline
  -> scene progress
  -> camera / UI / typography states
  -> browser frame
  -> image sequence
  -> FFmpeg video + generated audio
  -> MP4 + cover PNG
```

### 7.3 失败处理

- 渲染前检查字体、Logo、音频和浏览器依赖；缺失时立即停止并显示具体路径。
- 输出到临时目录，帧数、尺寸和时长验证通过后再生成最终成片。
- FFmpeg 合成失败时保留图片序列和音轨，便于重新合成。
- 不覆盖同名源素材；最终视频允许显式重建。

## 8. 声音设计

- 音乐：原创轻快电子节拍，前段建立脉冲，中段增强，11.5 秒进入品牌收束。
- 扫描：高频短扫频，与客户端识别同步。
- 点击：低频触感层加清晰短促 click。
- 数据路径：连续但克制的能量移动声。
- 节点完成：三个音高逐步上升的完成音。
- 最终成功：清脆品牌提示音，尾音在落版前结束。
- 总响度保持适合移动端播放，峰值不过载，对白频段不被过度占用。

## 9. 验证与验收

### 9.1 自动检查

- 使用 `ffprobe` 验证尺寸、帧率、时长、视频编码、音频编码和像素格式。
- 验证总帧数约为 450 帧。
- 在 0.0、1.3、4.2、7.0、11.5、14.0 秒导出关键帧。
- 检查最终文件可被系统播放器和浏览器解码。

### 9.2 视觉检查

- 关键帧无裁切、中文乱码、字体闪烁、元素穿帮或颜色跳变。
- Codex 识别、按钮点击、三个配置节点与完成标记清晰可读。
- 运动模糊不会遮住核心文案。
- 抖音安全区内没有关键内容被平台 UI 覆盖。
- 末帧主文案稳定停留至少 1 秒。

### 9.3 视听检查

- 扫描、点击、节点完成和品牌收尾均与对应动作同步。
- 音效层次清楚，无削波、爆音或突兀断尾。
- 静音观看时仍能完整理解产品核心价值。

## 10. 范围边界

本任务只制作一条 15 秒、9:16 的无限破甲 UI 产品动画及其可重复渲染源文件。横屏版本、方形版本、配音、真人镜头、多语言版本和正式发布上传不在本次范围内。
