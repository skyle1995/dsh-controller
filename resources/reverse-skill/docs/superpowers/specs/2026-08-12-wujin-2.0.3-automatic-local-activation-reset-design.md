# Wujin 2.0.3 Automatic Local Activation Reset

## Goal

Remove the manual `%LOCALAPPDATA%` recovery step when Windows DPAPI can no
longer decrypt the local activation identity and the signed receipt cannot be
used for the existing old-device recovery flow.

## Scope

- Change only the Windows client. Do not change or deploy the license server.
- Keep the existing signed-receipt deactivate-before-activate recovery path.
- When neither the identity nor receipt is usable, quarantine the old local
  entries under the application-owned `license/recovery` directory, create one
  new DPAPI-protected identity, and submit the entered CDK through the existing
  `/license/activate` endpoint.
- Keep the new identity stable after CDK, network, or receipt-save failures so
  retries never generate a sequence of device identifiers.
- Preserve the server's existing one-CDK/one-device decision. A server-side
  `device_already_bound` response remains an activation failure.

## File Safety

Quarantine operations hold no-follow handles for the license and recovery
directories. A normal file or reparse entry is moved as a directory entry; a
reparse target is never opened or modified. Readable identities are never
replaced.

## Verification

- Reproduce unreadable identity plus damaged receipt and prove activation now
  reaches the existing Keygate activate route.
- Prove the replacement identity remains stable after network failure.
- Prove quarantining a receipt reparse entry preserves its external target.
- Re-run Windows identity, Tauri activation, Rust workspace, UI, supply-chain,
  release-readiness, and final PE verification gates before rebuilding 2.0.3.
