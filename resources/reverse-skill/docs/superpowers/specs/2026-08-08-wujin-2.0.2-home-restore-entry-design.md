# Wujin 2.0.2 Home Restore Entry Design

## Goal

Move the paid environment restore action from the configuration result page to the primary action area on the Break Center home page, immediately beside the `一键破甲` button.

## User Interface

- The home hero renders a stable two-button action row.
- `一键破甲` remains the red primary action.
- `还原环境` is an outlined secondary action immediately to its right.
- `还原环境` remains visible but disabled when there is no ready restore session, while configuration or restoration is busy, or while the product is not activated.
- Clicking the enabled action opens a confirmation dialog explaining that only paid configuration and the paid `reverse-skill` tree are restored; free modules and their state remain unchanged.
- The result page no longer exposes a second restore action.

## State And Flow

1. The button reads readiness from `bootstrap.restoreSession.status === "ready"`.
2. Confirmation calls the existing typed `restoreConfiguration()` IPC command.
3. After the command returns, the UI refreshes bootstrap state.
4. The home page displays a compact result dialog containing restored, conflict, and failed counts.
5. Conflict and failed paths remain available in the result dialog without exposing CDKs or server response text.

## Error Handling

- A failed IPC call produces a user-visible restore failure message and leaves the current restore session available for retry.
- The action remains guarded against duplicate clicks while the application is busy.
- Existing core conflict behavior remains unchanged: post-configuration user edits are preserved rather than overwritten.
