# 激活页用户协议提醒设计

## 目标

新用户在激活后必须经过一次用户协议提醒，避免在未注意协议勾选框时直接进入配置页，同时保持操作足够简单。

## 已确认交互

1. 页面上的“已了解用户使用协议”复选框初始为未勾选，状态只存在于当前 `ActivationPage` 组件中。
2. 未激活时，“下一步：开始配置”仍然禁用。
3. 已激活但未勾选协议时，点击“下一步：开始配置”：
   - 不进入配置页；
   - 弹出“请先阅读并同意用户使用协议”提醒；
   - 同时自动将页面协议复选框勾选。
4. 用户点击弹窗中的“知道了”后留在激活页；再次点击“下一步：开始配置”时进入配置页。
5. 用户如果提前手动勾选协议，点击“下一步：开始配置”直接进入配置页，不显示提醒。
6. 关闭并重新进入或重新挂载激活页后，协议状态恢复为未勾选；不写入全局状态、缓存或磁盘。
7. “购买激活码”和协议链接不受协议勾选状态影响。

## 方案比较

- 采用现有样式的应用内提醒弹窗：外观与当前激活结果弹窗一致，自动勾选后由用户关闭，再次点击下一步。此方案行为清晰、改动小，作为实现方案。
- 使用系统 `window.alert`：代码更短，但视觉和键盘行为不受应用控制，不采用。
- 直接禁用“下一步”：无法在用户点击时解释原因，也不符合“弹窗提示后自动勾选”，不采用。

## 实现边界

- 仅修改 React 激活页的局部展示状态和对应 UI 测试。
- 不修改 CDK 验证、激活缓存、导航状态机、购买链接或后端接口。
- 复用现有 `.modal-backdrop`、`.modal`、`.modal-icon` 和 `Button` 样式，不增加新依赖。

## 状态与数据流

- `agreementAccepted`：初始为 `false`，由页面复选框控制。
- `agreementReminderOpen`：初始为 `false`，控制协议提醒弹窗。
- 下一步处理函数首先检查 `agreementAccepted`。为 `false` 时同时设置 `agreementAccepted = true` 和 `agreementReminderOpen = true`，随后返回；为 `true` 时调用 `onNavigate("configure")`。
- 提醒弹窗的“知道了”仅关闭 `agreementReminderOpen`，不触发导航。

## 验收与测试

- 真实 DOM 测试覆盖：已激活且未同意时不导航、自动勾选并显示提醒；关闭提醒后再次点击可导航；未激活时按钮禁用。
- 源码回归测试覆盖：复选框不是 `defaultChecked`，提醒文案、自动勾选和配置导航均存在。
- 运行 UI 全量测试、TypeScript 类型检查、Vite 构建和 Debug 客户端启动检查。
