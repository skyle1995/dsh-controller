# Cursor、Cline、Windsurf 版本门禁适配器设计

## 目标

按照原版项目的配置边界，将 Cursor、Cline、Windsurf 从静态占位项升级为真实客户端适配器。适配器负责检测安装状态和版本，但只有经过固定版本实机验收的客户端才允许自动写入配置。

## 原版约束

- Cursor 的全局规则由 `Settings → Rules → Global Rules` 管理。
- Cline 的规则由 `Settings → Custom Instructions` 管理。
- Windsurf 的规则由 `Global Rules` 管理。
- 无法确认稳定路径或格式时，不修改 SQLite、扩展 global storage 或其他内部状态文件。
- 未经过固定版本实机验收时，不得显示为支持，也不得宣称配置成功。

## 适配器结构

为三个客户端分别创建 `CursorAdapter`、`ClineAdapter`、`WindsurfAdapter`，并注册到 `ConfiguratorService.adapters`。

每个适配器提供：

- 安装检测：检查该客户端已知的安装标记或扩展目录。
- 版本检测：从可验证的可执行文件或扩展清单读取版本。
- 版本门禁：仅允许显式列入适配器白名单的版本进入配置流程。
- 配置结果：未安装显示“未检测到”；已安装但版本未验收显示“检测到版本，但当前版本尚未完成实机验收”。

## 当前阶段行为

由于本机没有安装对应客户端，当前白名单保持为空。三个适配器可以正确检测和报告状态，但不会写入任何客户端配置文件。模拟文件测试只验证检测、版本解析、拒绝未验收版本以及零写入，不替代实机验收。

## 后续实机验收

每个客户端安装后，针对具体版本执行：

1. 确认规则与 MCP 配置的真实持久化位置和格式。
2. 验证结构化合并、备份、回读和回滚。
3. 重启客户端验证配置实际生效。
4. 将通过验收的精确版本加入白名单。

只有完成以上四步，该客户端才会在界面中变为可勾选。

## 验证

- 三个客户端由真实适配器提供检测结果，不再由 `UNSUPPORTED` 静态列表生成。
- 未安装时保持不可选择。
- 模拟检测到版本但白名单为空时保持不可选择。
- 未验收版本执行配置时返回 `UNSUPPORTED`，且不创建或修改任何配置文件。
- Claude、Codex、Kiro 的现有行为和完整测试不受影响。
