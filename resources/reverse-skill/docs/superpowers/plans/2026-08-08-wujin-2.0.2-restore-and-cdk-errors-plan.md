# Wujin 2.0.2 Restore and CDK Error Mapping Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add a persistent, conflict-aware restore action for the paid one-click environment and make Keygate CDK failures actionable, then build the formal 2.0.2 package.

**Architecture:** A new `wujin-core` restore-session module owns snapshot manifests, hashes, path validation, and atomic restoration. Tauri creates/completes/loads the session and exposes one restore command under the existing configuration write lock. The result page consumes a typed restore summary. Keygate parsing stays in `online_activation.rs`, with canonical error codes passed unchanged to the existing UI mapper.

**Tech Stack:** Rust 2024, Tauri commands, React/TypeScript, serde JSON, SHA-256, existing atomic transaction/path-guard helpers, PowerShell release gates.

## Global Constraints

- Restore only reverses paid client configuration and the paid `reverse-skill` tree.
- `free-skills` and its ownership state are never touched by restore.
- Restore refuses to overwrite post-configuration user changes; conflicts remain untouched.
- Raw CDK values and raw Keygate response messages never enter logs or UI.
- Preserve existing atomic-write, path confinement, reparse-point rejection, and configuration lock guarantees.
- Do not add alternate domains, automatic retries, or server-side license changes.
- Do not create a formal release until the full automated gate passes.
