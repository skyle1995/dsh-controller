# Wujin 2.0.3 DPAPI Recovery Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a verified Windows 2.0.3 executable that automatically replaces an unreadable DPAPI activation identity after the user re-enters the same CDK, while keeping one Keygate device binding.

**Architecture:** Add recovery-only receipt verification and `/license/deactivate` support in `wujin-core`; add reversible identity replacement in `wujin-windows`; retain recoverable initialization state in Tauri and execute deactivate-before-activate from the existing activation command. Keep the UI contract stable except for actionable local-recovery errors.

**Tech Stack:** Rust 2024, Tauri 2, Windows DPAPI, Reqwest/Rustls, React/TypeScript, PowerShell release gates.

## Global Constraints

- Keygate production API remains `https://api.codexpojia.com/api/v1`.
- Product ID remains `244fc857-83c3-4462-9af9-a696f5065eec`.
- Recovery requires a Keygate-signed receipt plus a user-entered CDK.
- Deactivate happens before activate; Keygate never has two bindings.
- No CDK, receipt token, DPAPI seed/blob, or signing private key enters logs or fixtures.
- Old local files are copied to an app-owned recovery directory before replacement.
- Existing seven-day offline receipt behavior remains unchanged.
- Release version is exactly `2.0.3`.
- Refresh free and paid Skill inputs before activation implementation; every
  refreshed source remains commit-pinned, licensed, offline-complete, and
  covered by the existing paid/free isolation gates.
