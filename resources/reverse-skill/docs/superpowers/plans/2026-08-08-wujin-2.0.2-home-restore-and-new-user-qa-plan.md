# Wujin 2.0.2 Home Restore And New-User QA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the paid restore action beside the home-page one-click action, remove the duplicate result-page action, and verify the complete 2.0.2 experience from a clean-user perspective.

**Architecture:** `HomePage` owns the restore confirmation and feedback state while reusing the existing `restoreConfiguration()` and `bootstrap()` API contracts. The core restore service, Tauri command, paid configuration service, Keygate activation service, and free-module service remain unchanged. Existing focused and full release gates provide the clean-user evidence.

**Tech Stack:** React 19, TypeScript, happy-dom, Node test runner, Rust 2024, Tauri 2, PowerShell release scripts.

## Global Constraints

- `一键破甲` remains the red primary action.
- `还原环境` is the outlined secondary action immediately to its right.
- The restore button is always visible and is enabled only for an activated, idle client with a ready restore session.
- Restore only reverses paid client configuration and the paid `reverse-skill` tree.
- Free modules and their installed state remain unchanged.
- The result page must not expose a duplicate restore action.
- No CDK value or raw server message may enter UI feedback or logs.
- A formal package is built only after all focused and complete gates pass.
