# Wujin 2.0.1 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refresh the approved paid and free embedded projects, detect official Cursor installations on non-C drives, and produce a verified local Windows `2.0.1` formal package.

**Architecture:** Keep Windows registry discovery in `wujin-windows` and pass validated Cursor manifest candidates into the platform-neutral `wujin-core` registry. Refresh vendored upstream content only at approved immutable commits, regenerate all supply-chain evidence, then update every enforced version surface before running the existing release gate and package builder.

**Tech Stack:** Rust 2024, Tauri 2, `winreg`, PowerShell 5.1-compatible release scripts, TypeScript/Vite, deterministic ZIP assets, Ed25519 trust roots, Authenticode.

## Global Constraints

- Work only in `G:\AI\520reverse-skill\.worktrees\wujin-v2.0-windows` on `codex/wujin-v2.0-windows`.
- Preserve all unrelated untracked operational assets and `launcher-rs/target-remaining-days-test/`.
- Paid and free embedded content remain isolated.
- CDK, legacy CDK, receipt, and update public keys remain independent; no private key or issued CDK inventory enters source or customer artifacts.
- Cursor discovery does not scan all drives and does not hard-code a drive letter.
- The requested deliverable is a local formal package; public manifests, website links, mirrors, and GitHub releases remain unchanged.
- Production build approval is `APPROVE_WUJIN_2.0.1_PRODUCTION_BUILD`.
