# 无限破甲 2.0.0 macOS 开发交接

本文用于把 `AAnything001/wuxianpojiaapp` 的 `2.0.0` Rust/Tauri 源码交给 macOS 开发者。当前 `main` 是 Windows 实现基线，不代表已经存在可发布的 macOS 客户端、DMG、Apple 签名或公证产物。

## 1. 固定交付契约

- 产品版本：`2.0.0`
- 产品 ID：`wujin-reverse-skill`
- 桌面技术栈：Rust 2024、Rust `1.97`、Tauri 2、React 19、Vite 6
- 激活格式：`WJP1`；客户端只保存和使用验签公钥
- 在线权益格式：`WJD1`；设备绑定、刷新、撤销和可信时间由许可服务决定
- 更新：只检查签名清单、提示新版本并打开官网；客户端不下载或安装更新
- 免费与付费配置：独立 IPC、目录、状态、备份、回滚和 bundle，禁止交叉读写
- 用户文件：先校验路径，再备份、原子写入、回读；任一目标失败只回滚该目标

开发者从 `main` 创建独立分支，不在 Windows 发布分支直接替换平台实现：

```bash
git clone https://github.com/AAnything001/wuxianpojiaapp.git
cd wuxianpojiaapp
git fetch origin --prune
git switch -c macos/2.0.0 origin/main
rustup toolchain install 1.97
rustup override set 1.97
```

## 3. 推荐的移植边界

新增 `launcher-rs/crates/wujin-macos/`，通过明确接口提供以下能力，不要在 `commands.rs` 中散布 `cfg(target_os = "macos")`：

```rust
pub trait PlatformRuntime {
    fn user_paths(&self) -> Result<UserPaths, PlatformError>;
    fn protect_device_secret(&self, plaintext: &[u8]) -> Result<Vec<u8>, PlatformError>;
    fn unprotect_device_secret(&self, ciphertext: &[u8]) -> Result<Vec<u8>, PlatformError>;
    fn atomic_replace(&self, target: &Path, bytes: &[u8]) -> Result<(), PlatformError>;
    fn open_https(&self, url: &Url) -> Result<(), PlatformError>;
    fn copy_text(&self, text: &str) -> Result<(), PlatformError>;
}
```

平台错误应转换成现有稳定的 `AppError`/错误码。UI 不判断操作系统，也不接收任意 renderer URL、文件路径或 shell 命令。

### macOS 对应实现

| Windows 当前能力 | macOS 实现要求 |
| --- | --- |
| `USERPROFILE` / `APPDATA` / `LOCALAPPDATA` | 使用系统 API 解析 home、`~/Library/Application Support` 和 `~/Library/Caches`；测试可注入临时根目录 |
| DPAPI/CNG 设备私钥 | 使用 Keychain Services，`kSecClassGenericPassword`，service 固定为产品 ID，account 使用安装 ID |
| `ReplaceFileW` / `MoveFileExW` | 同一文件系统内写临时文件、`fsync`、权限校验、原子 `rename`，然后回读验证 |
| `ShellExecuteW` 打开 HTTPS | 使用受控的 Tauri opener 或 `NSWorkspace`；仍由 Rust 端按 link ID 解析 allowlist |
| Win32 剪贴板 | 使用 Tauri clipboard 插件或 NSPasteboard 的 Rust 封装 |
| UAC / PowerShell | 普通用户目录操作不提权；确需特权时定义独立、最小化 helper，不调用拼接 shell |
| WebView2 预检 | 使用系统 WKWebView/WebKit；启动时检查最低 macOS 版本和架构 |
| winget | 优先官方应用/CLI 检测；安装入口可引导 Homebrew 或官网 DMG，不静默执行未知包 |
| Windows 启动项 | 使用 `SMAppService`；开发阶段不写 LaunchAgent 文本作为生产方案 |
| Win32 进程/CDP 探测 | 使用 `NSRunningApplication`/`sysinfo` 或受测的原生封装，并校验 bundle ID、可执行路径和监听进程归属 |

## 4. 目录与客户端配置

所有实际路径必须先探测再写入。下面是开发候选，不是无条件硬编码值：

```text
home                         = $HOME
application_support         = ~/Library/Application Support
caches                      = ~/Library/Caches
codex_config                = ~/.codex/config.toml
codex_agents                = ~/.codex/AGENTS.md
claude_config               = ~/.claude/
cursor_support              = ~/Library/Application Support/Cursor/
wujin_state                 = ~/Library/Application Support/wujin-reverse-skill/
```

每个客户端适配器必须保留现有规则：仅操作用户明确选择且已探测到的客户端；解析 TOML/JSON 后合并；用户自有同名目录返回冲突；写前备份；写后回读；失败回滚；日志不记录配置正文、token、CDK 或完整隐私路径。

路径安全至少覆盖：

- `..` 路径穿越和绝对路径逃逸
- symlink 指向允许根目录外
- 大小写不敏感卷和大小写敏感卷
- iCloud/网络卷或跨卷 rename
- 文件锁、只读目录和权限变化
- Unicode 正规化后的同名路径

## 5. 激活、设备身份与服务端

不要改变 `WJP1` canonical JSON、Ed25519 验签、产品 ID 或 `1.x` 兼容规则。生产签名私钥、完整 CDK、归档密钥和管理员凭据不得进入 macOS 仓库、应用 bundle、日志、测试夹具或 CI artifact。

macOS 设备身份建议：

1. 首次运行在本机生成 Ed25519 设备密钥。
2. 私钥写入 Keychain，应用状态仅保存公开标识和服务端返回的签名权益。
3. 激活和刷新请求用设备私钥证明持有权。
4. Keychain 项丢失、被替换或不可读时关闭激活流程，不生成可迁移的明文备份。
5. 用独立测试 key 验证首次绑定、同设备幂等、异设备拒绝、撤销、过期和时钟回拨。

许可 API 的公开部署和接口说明见 `services/license-api/DEPLOYMENT.md`。macOS 客户端只调用公开的激活/刷新/健康接口，不接触管理员和 signer socket 路由。

## 6. 构建与测试

开发依赖：Xcode Command Line Tools、Rust `1.97`、Node.js、npm。Tauri 的 Apple prerequisites 以所锁定 Tauri 2 版本的官方要求为准。

```bash
xcode-select --install
rustup target add aarch64-apple-darwin x86_64-apple-darwin
cd launcher-rs/ui
npm ci --ignore-scripts
npm test
npm run build
cd ..
cargo fmt --all -- --check
cargo clippy -p wujin-core -p wujin-update -p wujin-provider -p wujin-cursor -p wujin-skin --all-targets -- -D warnings
cargo test -p wujin-core -p wujin-update -p wujin-provider -p wujin-cursor -p wujin-skin
```

在 `wujin-macos` 和 Tauri 接线完成前，不把 Windows workspace 全量 `cargo test --workspace` 作为 macOS 可通过门禁，因为当前 `wujin-windows` 直接使用 Win32 API。完成移植后应让平台依赖使用 target-specific dependency，并在 CI 中分别运行：

```text
macos-14 / aarch64-apple-darwin
macos-13 / x86_64-apple-darwin（若继续支持 Intel）
windows-2022 / x86_64-pc-windows-msvc（防止回归）
```

必须新增的 macOS 测试：

- Keychain 创建、读取、缺失、篡改和拒绝访问
- 原子写入、symlink 逃逸、回读失败和逐目标回滚
- 六客户端探测与“未选择不落盘”
- 免费/付费 managed block 字节级互不影响
- 更新清单有效签名、错误签名、错误 host、同版本和降级
- 外链只接受 Rust 端固定 link ID
- Apple Silicon 与 Intel 路径差异
- 应用重启后的激活、Provider、皮肤和备份恢复状态

## 7. Apple 发布边界

开发构建通过不等于可分发。正式交付另需主人批准并完成：

1. 固定 bundle identifier、最低 macOS 版本和支持架构。
2. 使用 Developer ID Application 证书签名 `.app` 及全部嵌套代码。
3. 生成 DMG 或 PKG 后提交 Apple notarization，并 staple ticket。
4. 验证 Gatekeeper：`codesign --verify --deep --strict`、`spctl --assess`、`stapler validate`。
5. 在干净 macOS 账户验证首次启动、Keychain、网络失败、升级和卸载后数据边界。
6. 记录产物 SHA-256、字节数、签名 Team ID、公证 request ID 和测试矩阵。
7. 最终下载地址确定后，再生成和签署更新清单；清单只指向官网，不包含自动安装命令。

证书、私钥、notarization 凭据和生产公钥注入材料只放 CI secret 或受控发布机，不提交 Git。
