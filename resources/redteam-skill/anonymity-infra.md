# 匿名化与基础设施(OPSEC)

核心思想:**分层**——扫描层(可弃)、打点层(半弃)、长控层(核心资产,永不直接暴露)。
**红线:攻击链上任何一层被ban,不影响其它层与核心资产**。

## 一、资产分层

| 层 | 用途 | 数量 | 特征 |
|---|---|---|---|
| 扫描层 | masscan/nuclei 大流量 | 每次 3-5 个 VPS | 用完即弃,与后层无关联 |
| 打点层 | 漏洞利用初始连接 | 每目标独立 | 目标封了就换,不心疼 |
| 中转层 | 载荷回连第一跳 | 2-3 个常驻 | 域前置/CDN 前置隐藏 |
| 核心层 | 团队服务器/数据 | 1 个,永不出现在目标日志 | 只接受中转层连接 |

## 二、代理链构建

```bash
# 多跳链:proxychains 配置
# vim /etc/proxychains.conf
socks5 127.0.0.1 1080      # 本地 chisel 出口
socks5 10.x 1081            # 再经一台家庭宽带走
# 住宅/移动出口(最难封):
#  - 自建:4G 路由器 + openvpn(出口IP=运营商池,天然轮换)
#  - 商用:住宅代理池(按流量),绑定测试浏览器指纹用
# 证书与域名:每目标独立域名,证书 Let's Encrypt 批量
```
- **不出核心层 IP**:所有对外服务经 CDN/域前置;团队服务器只白名单中转层

## 三、指纹与关联去除

- 每层 VPS 不同的:时区/主机名/语言(`timedatectl`、locale)
- 扫描工具 UA/速率特征各异(别所有目标同一套 masscan 参数)
- 域名 whois 隐私保护、注册邮箱分层、不吃同一个付款卡
- **凭据隔离**:每层不同 SSH key/密码;会话记录分目录

## 四、操作纪律
1. 打点前过一遍:该动作出现在目标日志里的 IP 是哪层?被封影响什么?
2. 长控层永不发起扫描/爆破;只静静收 implant
3. 每个目标的工具、载荷、域名互不复用(哪怕方便)
4. 项目结束:中转层以下全销毁,核心层数据归档加密

## 红线(完成判定)
- 任一中转层模拟被封:切换后 10 分钟内通道恢复(预案演练过)
- 目标侧日志中找不到核心层 IP/域名任何记录
- 基础设施清单(层/用途/销毁时间)已入档 runs/infra.md
